## Проверено через коннектор

Новый фрейм, 25 отдельных image rectangles, 25 кликабельных Pinterest-источников и отдельный редактируемый текст. Одна загрузка завершилась таймаутом: после readback пустого объекта повторён только её upload в тот же объект. Итоговый readback подтвердил все 25 изображений; композиция проверена.

Коннекторная проба проверяется отдельно от локального плагина.

## Проверено через локальный плагин

Длинные подписи сначала перекрывали ссылки: native resize сбрасывал textAutoResize. Порядок изменён на resize → HEIGHT в ядре и собранном code.js. Уже созданный фрейм исправлен точечно через коннектор; итог 1776×2017, пересечений подписи/ссылки нет, screenshot проверен. Квитанция `output/playwright/g1/figma-native-plugin-receipt.json` различает native-import и эту коррекцию.

## Текущий локальный плагин v2

`plugin/manifest.json` — development manifest для Figma Desktop. Нужен только разрешённый dev-доступ к `http://localhost:8787`. Сервер слушает только IPv4 loopback 127.0.0.1. Плагин не управляет Pinterest и не получает браузерную авторизацию. Код из приложения разрешает загрузить один зафиксированный набор до 25 изображений; package содержит исходные URL и SHA файлов.

1. Из корня проекта выполнить `npm run build`, затем `npm start`.
2. В PMA выбрать изображения и нажать «Экспорт выбранного». Раскрыть «Код подключения Figma».
3. В Figma Desktop открыть нужный Design-файл.
4. При первой установке: главное меню Figma → Plugins → Development → Import plugin from manifest, выбрать `spikes/figma-g1/plugin/manifest.json`. Повторно импортировать manifest не нужно.
5. Запустить «PMA — локальная проба импорта» из Development.
6. В отдельном окне вставить код, нажать «Загрузить и сверить подборку», затем «Создать или завершить фрейм».
7. Повторная загрузка той же попытки сверяет существующий фрейм. Второй фрейм автоматически не создаётся. Код действует 15 минут; обновляется в PMA для прежнего набора.

Имя фрейма включает проект и задание. Если есть ручные изменения, удаление, потеря меток или legacy-фрейм той же подборки, плагин сообщает конфликт. Старые объекты не исправляются автоматически. Для отдельного нового фрейма использовать «Отдельный новый импорт в Figma» в PMA, подтвердить создание и загрузить новый код. Максимум три попытки на снимок. Сообщение о коннекторном импорте не считается доказательством native-плагина.

## Код и ограничения

`build-frame.mjs` — ядро раскладки; `import-managed.mjs` — проверка/восстановление native-фрейма. Локальная проба использует Inter без библиотек. После изменения исходников выполнить `node scripts/build-plugin.mjs`: он собирает `plugin/code.js` из ядра и `plugin/handler.js`, а `plugin/ui.html` — из `plugin/ui.template.html` и переносимого `sha256.mjs`. Сгенерированные code.js/ui.html вручную не редактировать.

UI sandbox Figma не предоставляет `crypto.subtle`; SHA-256 выполняется переносимой функцией, проверенной по стандартным векторам и Node crypto. Собранный UI отдельно протестирован без Web Crypto: правильное изображение загружается, изменённое останавливается до обращения к native-плагину. После обновления файлов закрыть и заново запустить окно плагина. Если код истёк, в PMA выбрать «Код подключения Figma» → «Обновить код этого набора» и заменить код в плагине; это не создаёт новую попытку.

Обмен UI/native использует `pluginMessage`, channel экземпляра UI и requestId. Не проверять `event.source === parent`: вложенная оболочка Figma не гарантирует такое равенство. Тесты проверяют прямые/пересланные/synthetic ответы и игнорирование постороннего channel. Сообщение «Сверяем набор с открытым файлом Figma…» ограничено 90 секундами; неизвестный результат не запускает новый импорт автоматически.

`upload-assets.mjs` — одноразовые загрузки по URL подключённого Figma. Приватная конфигурация удаляется после запросов; в квитанциях нет signed URLs.

Семь автоматических тестов проверяют native-совместимое ядро: создание, повтор, частичную загрузку, ручные правки, удаление/потерю меток, незавершённую структуру и явный отдельный импорт. Ещё семь проверяют SHA-256 и собранный UI/native-обмен. Всего в проекте 98 тестов. Изоляция на другом аккаунте/ПК и глобальная идентификация копий документов остаются открытыми. См. [ADR 0007](../../context/architecture/06-решения/журнал-решений/2026-11-05-независимые-экспорты.md).

## Если плагина ещё нет в меню

Ниже — история диагностики установки; текущий успешный результат описан выше.

Команда Import plugin from manifest сначала открывает окно выбора файла. В поле «Имя файла» вставить полный путь к manifest.json и нажать «Открыть». Только после этого plugin появляется в Development. Кнопки загрузки/создания находятся в отдельном окне запущенного плагина, а не на холсте подборки. При ошибке нужен её точный текст; удачный коннекторный фрейм не считается запуском этого окна.

## История: ошибка manifest.api

2026-11-02: при импорте Figma сообщила, что api имеет значение undefined. Проверка исходного plugin/manifest.json в двух процессах подтвердила строку api=1.0.0, UTF-8 JSON и наличие code.js/ui.html. Сначала в localFileExtensions Figma был зарегистрирован только служебный manifest из каталога Codex IwaKeyDistribution, у которого api отсутствует.

Повторная диагностика через Computer Use и чтение путей localFileExtensions показала четыре записи: служебный manifest Codex, правильный PMA manifest, а также ошибочно выбранные code.js и ui.html. Наличие PMA в этом списке подтверждает регистрацию пути, но не принятие манифеста валидатором Figma. Следующий скриншот пользователя показал «Manifest issue» именно в подменю PMA: для дальнейшей диагностики требуется «Show error details…» у PMA. Повторять импорт без подробностей ошибки не следует. code.js и ui.html отдельно не импортируют. Настройки Figma и служебный манифест Codex не изменялись. Живой запуск пока не подтверждён: Computer Use читает accessibility, но захват окна и клики завершаются ошибками window capture timed out и coordinate input geometry is unavailable.

## История: ошибка devAllowedDomains у PMA

После открытия Show error details и переключения на Console чтение accessibility показало собственную ошибку PMA: `Manifest error: Invalid value for devAllowedDomains. 'http://127.0.0.1:8787' must be a valid URL.` В manifest и fetch окна плагина адрес заменён на `http://localhost:8787`, как в официальном примере для development-сервера. Путь регистрации плагина сохраняется; его принятие и живой запуск нужно проверить повторным открытием Development.

Прямая проверка после правки: manifest и fetch используют одинаковый origin localhost:8787; JavaScript code.js и ui.html разбирается без синтаксических ошибок; GET localhost:8787/figma-package.json с Origin: null возвращает 200, CORS * и технический пакет из 25 изображений. Это проверка локального сервиса, не доказательство успешного запуска внутри Figma.

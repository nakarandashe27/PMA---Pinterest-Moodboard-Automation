## Находки

### F1 (P2). Диалог закрывается от клика внутри окна, черновик теряется — исправлено

- Где: `src/components/Modal.tsx:10` (было `:6`, `onClick` по `event.target===event.currentTarget`).
- Как воспроизвести: открыть «Открыть своё подключение» и ввести название. Затем кликнуть в белый отступ окна (26 px от края) или выделить текст в поле мышью и отпустить кнопку на затемнённом фоне.
- Ожидается: окно остаётся открытым, черновик на месте. Закрывает только клик по подложке.
- Было: окно закрывалось. После повторного открытия поле снова «Мой Pinterest». Это воспроизведено во встроенном браузере на временном сервере. Затрагивает все диалоги: подключение (пароли), замысел (`BriefDialog`, длинный текст), замену, экспорт, настройки AI. У `<dialog>` подложка и отступ — один и тот же элемент, а `click` после перетаскивания приходит общему предку.
- Исправление: окно закрывается, только если нажатие и отпускание оба произошли вне прямоугольника окна.
- Проверка: `server/test/review-2026-11.test.mjs` R5 — клик в отступ, выделение с выходом за край, затем настоящий клик по подложке.

### F2 (P2). «Настройки AI» падают с 500 при утраченном ledger — исправлено

- Где: `server/ledger.mjs:47`, `:50`. Вызов — `server/app.mjs:181`.
- Как воспроизвести: в проектной БД есть `ledger-binding`, а `accounting/ledger.sqlite` удалён (сценарий D17). Затем `GET /api/ai/profile` от владельца.

- Было: 500 «Ошибка локального сервиса» и `TypeError: Cannot read properties of null (reading 'prepare')` в `usedInMonth`. Конструктор `Ledger` в этом случае оставляет `db=null`, а `usedInMonth`/`monthSpend` к нему обращаются. В итоге владелец не видит, почему AI закрыт, именно в том сценарии, ради которого есть блокировка.

### F3 (P2). Node-инспектор в установленной программе — открыто

- Где: `package.json:76` (`build.electronFuses` без `enableNodeCliInspectArguments:false`). Решение записано в `desktop/RELEASE.md:17`.
- Как воспроизвести: `npm run desktop:dist` (собирается в `release/` этой рабочей копии), затем `npx @electron/fuses read --app release/win-unpacked/PMA.exe` → `EnableNodeCliInspectArguments is Enabled`. Запуск `PMA.exe --inspect=127.0.0.1:19229` на временном `PMA_DESKTOP_ROOT` → `http://127.0.0.1:19229/json/list` отдаёт «node.js instance».
- Риск: любой процесс или человек под той же учётной записью Windows получает код в main с `safeStorage` и может расшифровать API-ключ любого владельца PMA без его локального пароля. Граница между владельцами внутри одной учётной записи Windows держится только на UI. Проектная SQLite и так лежит открыто, а DPAPI доступен тому же пользователю, поэтому это не прорыв привилегий ОС. Но это лишний и общеизвестный путь.
- Почему не исправлено: на этом fuse держится автоматическая проверка установленной программы (`PMA_SMOKE_EXE`, Playwright `_electron`). Рекомендация: собирать выпуск с `enableNodeCliInspectArguments:false`, а смоук запускать на отдельной тестовой сборке. Либо прогонять смоук до переключения fuse через `@electron/fuses` на копии exe.

### F4 (P3). Адрес API `[::ffff:127.0.0.1]` проходил статическую проверку — исправлено

- Где: `server/ai-endpoint.mjs:19` (`publicAddress`), используется в `checkEndpoint` и `guardedLookup`.
- Как воспроизвести: `checkEndpoint('https://[::ffff:127.0.0.1]:8443/v1')`.
- Ожидается: отказ «Служебные, локальные и частные адреса для API запрещены».
- Было: возвращался `https://[::ffff:7f00:1]:8443/v1`. WHATWG URL записывает IPv4-mapped адрес в шестнадцатеричной форме, а регулярка ждала форму с точками. То же для `::ffff:a9fe:a9fe` (169.254.169.254) и `fec0::/10`. Профиль с таким адресом сохранялся.
- Почему не выше P3: проверка при соединении (`guardedLookup`) всё равно блокировала запрос. Скрипт с локальным слушателем на 127.0.0.1 не получил ни одного соединения, ключ не уходил. Это проверено.
- Проверка: R2.

### F9 (P3). `URIError` в `app://` — исправлено

- Где: `desktop/ipc-policy.mjs:51`.
- Как воспроизвести: `protocolTarget('app://pma/%E0%A4%A')`.
- Было: `URIError` вместо `{kind:'deny'}`. Эту функцию вызывают `protocol.handle`, `will-navigate` и `setWindowOpenHandler` (`desktop/main.mjs:101`, `:131`, `:135`). Исключение в `will-navigate` не вызывает `preventDefault`. Последствия ограничены: такую ссылку может породить только свой UI, и UI до неё не доходит. Но поведение не должно зависеть от этого.

## Что не проверено и почему

- Живые Pinterest, Figma и платный API (D12/D13/D20) — запрещено условиями ревью. Поведение плагина в настоящем Figma проверено только тестами на заглушках.
- Установка и обновление на чистом ПК и ПК архитектора — нет доступа. Установщик собран и проверен `verify-package`, но не устанавливался: смоук установленной программы (`PMA_SMOKE_EXE`) не запускался, чтобы не трогать `%LOCALAPPDATA%\Programs`.
- Окна отчётов AI после истечения 30-минутной сессии в desktop — по коду `clearPrivateScreen` вызывается только на `/active-connection` (`desktop/main.mjs:126`). Отчёт того же владельца, вероятно, остаётся открытым до смены аккаунта. Не воспроизведено: нужен ускоренный таймер сессии в настоящем Electron.
- Скринридеры (NVDA/JAWS) и экранная лупа Windows — проверка шла по дереву доступности и клавиатуре, без живого скринридера.
- Нагрузочные и долгие сценарии (40 прокруток Pinterest, 25 изображений по 8 МБ) — требуют живого Pinterest.
- Устойчивость `interpretation-ui.test.mjs` (известное зависание ~1/15) — в трёх полных прогонах не проявилось, отдельно не исследовалось.
- `GrantFileProtocolExtraPrivileges=false` (F17) и `enableNodeCliInspectArguments=false` (F3) на собранном exe — не пересобирались, потому что это решение по выпуску.

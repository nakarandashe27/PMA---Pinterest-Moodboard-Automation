| Pinterest/Figma | Условия доступных аккаунтов/приложений проверить; нулевую цену не обещать | Реальные операции | Не определено |
| Сервер | Не выбран, после пилота | Не определено | Не входит в текущую оценку |
| Сопровождение | Время разработчика и архитектора | Установка, исправления, повторный отбор | Учитывать отдельно |

## Распределение AI

На 2026-11-05 добавлены [явные попытки замены](../06-решения/журнал-решений/2026-11-05-точечные-замены.md): до трёх на исходную историю с учётом соседних веток/ошибок/отказов, до 20 кандидатов и одного дополнительного inference на попытку. Исходные примеры и до пяти отвергнутых кадров входят в тот же предел 24 МиБ. Живой пример дал 15 692 входных и 2 353 выходных токена, 50,199 секунды на модель. Это отдельный измеренный запуск, не оценка месячной стоимости или процента квоты.

| Задача | Модель | Лимит | Оптимизация |
|---|---|---|---|
| Интерпретация текста | Codex CLI, модель из доступного каталога; живая проверка `gpt-5.6-sol` | 90 секунд, один вызов на версию; уточнение отдельным явным вызовом | Короткая структура, готовый запрос без AI, reuse сохранённой версии |
| Анализ входных примеров | Мультимодальная, не выбрана | Размер/число изображений | Нужный crop и управляемые производные |
| Отбор кандидатов | По benchmark качества/цены | Максимум кандидатов/вызовов | Дедупликация до оценки, reuse в пределах владельца и версии модели |
| Замена | Тот же контекст задачи | Отдельное ограничение итераций | Только отмеченные карточки и новые кандидаты |

Не заявляются универсальные проценты экономии, точность «дешёвой модели» или скидки batch без выбранного провайдера и тарифа.

## Формулы

Цена запуска = сумма всех billable вызовов + передачи/хранения, если они тарифицируются. Цена полезного мудборда включает неудачные поиски, замены, повторную обработку и ручную правку. Общий расход делить на число действительно завершённых полезных наборов; при нуле завершённых наборов среднюю цену успеха не выдавать за ноль.

## Ограничения до платных тестов

Нужны заданные max cost per job/request, max candidates, max AI calls, max iterations и месячный предел. Уже реализованы конечные пределы количества/изображений/итераций прототипа и общий месячный счётчик; конкретные денежные значения/тариф API ещё не заданы. В desktop их задаёт владелец перед платной работой; отсутствие значения не означает unlimited.

Повторы входят в тот же бюджет. При достижении лимита сохранить результат и остановить новые платные шаги; продолжение — осознанное действие с обновлённым пределом. UI показывает фактический расход, если провайдер его позволяет получить, иначе помеченную оценку.

См. [бизнес-формулу эффективности](../../business/economics/unit-economics.md), [открытые вопросы](../06-решения/открытые-вопросы.md), [риски](риски-архитектуры.md), [roadmap](../08-дорожная-карта/roadmap.md).

## Резервирование и неопределённый расход

Дополнение 2026-11-05: для текущего Codex CLI согласован и реализован общий предел 100 inference в календарный месяц Europe/Moscow на экземпляр PMA. Атомарные неизменяемые резервы `ai-reservation` учитывают интерпретацию замысла, обычный отбор, замены и сравнительный скрипт; ошибки, отмены и unknown после начала не возвращают остаток. Старые вызовы учитываются консервативно, унаследованные рекомендации повторно не списываются. Конкуренция/перезапуск проверены без живых AI-вызовов. `PMA_AI_MONTHLY_CALLS` задаёт положительный конечный предел. Это локальная граница числа запусков, не денежная стоимость/квота ChatGPT.

Одна [реальная интерпретация текста](../06-решения/журнал-решений/2026-11-05-замысел-в-поисковый-запрос.md) через Codex CLI дала 9 762 input и 116 output tokens. Резерв ровно один, повтор открытия использовал сохранённый результат. Это отдельный вызов подготовки, AI-отбор не запускался. Полезность формулировки и выдачи ещё оценивает архитектор.

Пользователь запросил будущий второй режим OpenAI-compatible API со своим ключом для людей без подписки. Он ещё не реализован; до запуска нужны endpoint/model, проверка мультимодальной схемы и отдельный денежный/токенный предел. Автоматического перехода с подписки на API нет. [ADR 0008](../06-решения/журнал-решений/2026-11-05-изоляция-и-пределы-g2.md).

До каждого billable вызова исполнитель атомарно резервирует верхнюю оценку стоимости в бюджете задания и общего пула провайдера. Несколько параллельных оценок не могут независимо потратить один остаток. В расход входят платные ошибки и замены.

После ответа резерв сверяется с usage. При таймауте и неизвестной тарификации резерв не освобождается автоматически: до подтверждения используется консервативная оценка. Retry получает отдельный резерв в том же общем лимите. Stop/cancel запрещает новые вызовы; уже начатые учитываются до завершения/сверки.

Готовность: тест конкурентного резервирования, платной ошибки, таймаута и отмены показывает отсутствие превышения установленного предела. Число вызовов CLI проверено локальными тестами; резервирование денежной стоимости будущего API остаётся требованием, финансовый тест не проведён.

## Desktop API: согласованный контракт 2026-11-06

- Общий пул экземпляра пилота — до 100 inference/календарный месяц Europe/Moscow для интерпретации, отбора, замен и явной платной проверки подключения. В desktop можно выключить AI или уменьшить предел. Legacy env прототипа допускает другой конечный предел; его не менять молча.
- Денежный предел — owner/месяц, общий для меняемых им API-профилей. Снимок provider/model/wire format/тарифа/валюты/лимитов/входа неизменяем для резерва; смена профиля не начинает новый бюджет.
- До отправки атомарно резервировать слот и доказанную верхнюю стоимость input/image/output/reasoning и иных billable единиц выбранной модели. Если billing mapping/тариф/верхняя граница неизвестны, платный вызов блокируется. Один ручной тариф без понятной стоимости изображений не достаточен.
- После ответа сверять usage. Ошибка, отмена, unknown и отсутствие достоверного usage не возвращают остаток автоматически; SDK retry выключен, ready reuse не расходует вызов. Платная проба API подчиняется тем же правилам.
- Авторитетный ledger не восстанавливается старым project-backup поверх актуального учёта. Предложено отдельное accounting-хранилище с атомарным claim/reservation/debit operation ID; проект связывается до отправки, сбой между шагами учитывается консервативно. При утрате актуального ledger платный AI закрыт до сверки.
- Предел контролирует действия PMA по проверенным тарифам, не расход других программ с тем же ключом и не общий счёт провайдера. Валютные курсы/цены не угадываются. Нужны фактические настройки и согласованная ограниченная проба.

Эти требования ещё не реализованы и проверяются D12–D17 [desktop-приёмки](../06-решения/приёмка-десктопа.md). Автоматического платного fallback нет. Ключи/денежные операции в архитектурной сессии не выполнялись.

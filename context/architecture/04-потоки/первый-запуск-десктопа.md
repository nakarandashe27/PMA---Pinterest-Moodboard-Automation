# Первый запуск и восстановление десктопного PMA

Дата: 2026-11-06. **Согласованный целевой сценарий; мастер, установщик и API-режим ещё не реализованы.** [ADR 0011](../06-решения/журнал-решений/2026-11-06-десктопное-приложение.md).

## Условия пилота

Обычный установщик, вероятно Windows 10, доступны админ-права. Точный ПК проверяется до передачи; отсутствие подписки ChatGPT учтено выбором API-режима. Установленные Chrome и Figma Desktop — внешние зависимости. Интернет нужен для Pinterest, облачного AI и Figma; самостоятельный запуск не означает офлайн или автономные действия модели.

Инициатор один раз помогает настроить API/бюджет и Figma-плагин. Затем главный архитектор сама вводит задания, подтверждает поиск, выбирает и заменяет кадры, выполняет нужные экспорты. Участие разработчика в каждом обычном запуске не считается самостоятельным пилотом.

## Подготовка передачи

1. Подтвердить OS/build/x64, Chrome, Figma Desktop и возможность работы из её сети. Windows 10 проходит отдельную пробу установленного пакета по [матрице](../06-решения/приёмка-десктопа.md); версия ОС инициатора не подставляется вместо проверки.
2. Подготовить чистый installer и готовый Figma-плагин. В поставке нет developer .local/pma, G1 seed-пакета, аккаунтов, cookies, ключей, авторизаций, пользовательских фото и квитанций.
3. Определить доверенный источник, версию/контрольную сумму и подпись либо явно согласованный внутренний способ передачи. Не оформлять выпуск как готовый, пока порядок установки на целевом ПК не проверен. Автоматического обхода защит ОС нет.
4. Заранее выбрать действительный API endpoint/model и способ оплаты владельцем. Это настройка после текущей архитектурной сессии: ключи сейчас не создавались. Перенос developer ChatGPT/Codex-входа не нужен и не выполняется.

## Установка и первое открытие

| Шаг | Действие человека | Поведение PMA и результат |
|---|---|---|
| Установка | Запускает полученный installer | Устанавливает runtime/UI/готовый плагин и ярлык; пользователь не ставит Node/npm/Codex и не запускает сервер |
| Старт | Открывает PMA обычным способом | Single-instance lock, проверка версий данных/каталога/места, worker handshake. Новый экземпляр данных пуст и заблокирован |
| Диагностика | Просматривает понятные состояния | Версия PMA/ОС, Chrome, worker, доступность Figma bridge, готовность AI. Отсутствие зависимости даёт конкретное действие |
| Подключение | Создаёт подключение с отдельным паролем PMA | Пароль задаётся в форме; открывается отдельный профиль Chrome |
| Pinterest | Вручную входит в собственный аккаунт, возвращается и нажимает проверку | PMA фиксирует проверенную Pinterest-личность. Проверка/CAPTCHA выполняется человеком |
| AI | Совместно заполняют endpoint, wire format, model, ключ, тариф, валюту и месячный бюджет | Ключ уходит в защищённое хранилище; UI показывает статус/маску. До бюджета и проверки контракта платный AI выключен |
| Проверка API | Явно разрешает показанную пробу | Подготовленный ограниченный запрос резервирует вызов/стоимость. Проверяются текст, изображения и структура; сохранение ключа само не запускает inference |
| Figma | Открывает Design-файл, импортирует готовый manifest из указанной стабильной папки | Плагин появляется в Development; PMA проверяет версию протокола и выдаёт код только для выбранного снимка/попытки |

Платная проба учитывается в общем месячном пределе 100 и денежном бюджете. Недоступная модель, несовместимый API, неизвестная цена или исчерпание лимита не включают другой provider/model автоматически. Готовый запрос и чистый Lens сохраняют путь без AI; свободный замысел можно вручную преобразовать в запрос.

Админ-права допустимы при установке нужных программ, но PMA ежедневно запускается как обычное пользовательское приложение. Сбой Chrome после создания подключения сохраняет его и предлагает открыть тот же профиль; не создавать дубли и новый пароль ради повтора.

## Первая рабочая задача после настройки

1. Создать свой проект. Ввести замысел или выбрать готовый запрос; добавить примеры при необходимости.
2. Если используется подготовка замысла, явно запустить AI, прочитать/исправить формулировку и отдельно подтвердить поиск. Чистый Lens не подменяется текстом.
3. Дождаться конечной выдачи; просмотреть рекомендации/все кадры, сделать ручной выбор. При необходимости отметить места, найти и явно применить замены.
4. Зафиксировать выбранный снимок. Pinterest-save и Figma-import запускаются отдельно по нужному назначению.
5. Для Figma вручную открыть плагин, ввести свежий код, загрузить/сверить набор, затем создать или завершить фрейм. Проверить фактический результат и отдельные статусы двух назначений.

Эта новая проверка на другом ПК не должна пересоздавать старую доску 7/7 и фрейм 30:2 разработчика. Проверяются свои данные архитектора и разрешённые ею действия. Качество на пяти реальных задачах — отдельный [пилот G3](../../idea/04-mvp/success-metrics.md).

## Обычный повторный запуск

Открывается заблокированное PMA с сохранёнными подключениями; проекты доступны после своего пароля. Нет автоматического запуска Chrome/AI/поиска/экспортов только от открытия приложения. Повторный ярлык фокусирует существующее окно. Готовое сохранённое описание/оценка переиспользуется без inference.

Закрытие крестиком завершает приложение, операции и управляемый Chrome. Сохранённый выбор переживает выход; несохранённые изменения выбора должны быть явно обозначены и обработаны UI до завершения. Предлагается сохранять текущую допустимую revision перед штатным выходом; конфликт/ошибка не должны выдаваться за успех. Это уточнение механизма, проверяемое на реализации, а не существующее autosave.

## Паузы и сбои

| Ситуация | Действие и сохранность |
|---|---|
| Pinterest просит вход/проверку | Открыть исходное подключение, пройти вход вручную, нажать продолжение того же run. Owner не меняется, результаты/выбор сохраняются |
| Истекли 30 минут PMA / lock / смена A→B | Операции останавливаются, доступ и pairing отзываются. A-ответ не показывается B. После входа продолжение явное |
| Закрытие/падение во время AI | Начатый вызов и резерв остаются учтёнными; поздний ответ не применяется. Unknown автоматически не повторяется |
| Неизвестный экспорт Pinterest/Figma | Сначала readback/сверка в исходном назначении; обновление кода не создаёт новую попытку |
| Ручная правка/удаление объектов Figma | Конфликт, без перезаписи и восстановления поверх ручной работы. Новый фрейм — отдельное явное действие |
| Порт 8787 занят | Figma недоступна с понятной диагностикой; PMA не подключается к неизвестному listener и не завершает его |
| Недоступен API / закончился бюджет | Показать причину и сохранённые результаты; ручной просмотр/готовый запрос доступны, скрытого fallback нет |
| Мало места / повреждены данные | Остановить новые операции, сохранить читаемое состояние, предложить безопасную диагностику/восстановление; не удалять данные автоматически |
| Забыт локальный пароль | Доверенная локальная операторская процедура, без HTTP-сброса или обхода чужого подключения. Способ поставки этой процедуры проверяется до пилота; npm-команда не является desktop-инструкцией |

## Ручное обновление и backup

Инициатор передаёт новую проверенную версию. Владелец завершает PMA и старое окно Figma-плагина, запускает installer, затем открывает PMA снова. Корень данных и путь manifest стабильны.

Перед изменением схемы проверяется совместимость и свободное место; создаётся техническая копия согласованного закрытого состояния БД и связанных файлов. Не копировать один открытый SQLite без WAL/файлов. Restore не откатывает авторитетный учёт AI, отзывает сессии/pairing, сохраняет owner/snapshot/receipt и допускает только совместимую версию. При утрате ledger платный AI блокируется до сверки. Подробности — [стратегия данных](../05-стек/десктопное-приложение.md#данные-секреты-и-схемы).

Данные/профили не мигрируют из рабочего прототипа автоматически. Технический backup экземпляра не является переносимым пользовательским архивом. Перенос проектов между ПК, browser-входов и DPAPI-секретов не обещан.

## Удаление и помощь

Удаление приложения сохраняет локальные проекты, файлы и backup. Пользовательское удаление данных — отдельная функция с проверкой owner/ссылок; она пока не реализована. Внешние пины/доски/фреймы не удаляются этим действием. Автоматического TTL нет.

Владелец может создать и просмотреть безопасный технический отчёт, затем сам решить, кому его передать. В него не попадают ключи, cookies, коды, исходные тексты/изображения и сырые ответы провайдера. Автоматической отправки нет.

# Сохранение выбранных пинов

Статус: локальный DOM-адаптер реализован и проверен на семи выбранных изображениях; Pinterest API/scopes не используются. Постоянная доступность и второй реальный аккаунт остаются открытыми.

## Когда применять

Архитектор просмотрел набор, зафиксировал выбор, видит проект/аккаунт и запустил сохранение.

## Граница

Одна секретная доска на проект. Сохраняются существующие пины через обычный интерфейс Pinterest; скачанные копии заново не публикуются. Перед записью проверяются исходный аккаунт, владелец и видимый признак секретности. Имя ограничено 50 символами с устойчивым суффиксом проекта.

## Примеры

Корректно: проверить владельца и SECRET, сохранить выбранные ID и записать квитанции по каждому.
Некорректно: использовать последнюю открытую доску браузера или принять PUBLIC по умолчанию.

## Сбои

Отдельный статус каждого пина и всей попытки. После таймаута сначала сверить результат доступным подтверждённым способом; удалённый API не объявляется идемпотентным без проверки. Успешный импорт Figma не повторять из-за сбоя Pinterest. При невозможности сверки показать неопределённость, не докладывать успех.

Источник: [официальный Save Pin](https://github.com/pinterest/pinterest-python-generated-api-client/blob/main/docs/PinsApi.md#pins_save), [OpenAPI](https://github.com/pinterest/api-description/blob/main/v5/openapi.yaml) (проверено 2026-11-02).

См. [экспорт](../../04-потоки/сценарий-и-состояния.md), [права](../права-доступа.md), [эксперименты](../../06-решения/проверка-интеграций.md).

## Практическое уточнение

2026-11-05: оба назначения связаны с неизменяемым снимком ручного выбора, содержащим порядок и SHA asset. Pinterest хранит отдельные квитанции каждого сохранения. После таймаута выполняется чтение доски; неизвестный отсутствующий пин не сохраняется повторно автоматически. Неполная или устаревшая выдача допускает три чтения с паузой 600 мс, без повторной мутации. Удалённый вручную подтверждённый пин даёт конфликт. Живой результат: все семь изображений сверены на одной новой секретной доске. См. [ADR 0007](../../06-решения/журнал-решений/2026-11-05-независимые-экспорты.md).

В UI-пробе сохранённый экземпляр получил другой ID. Хранить sourcePinId и savedPinId отдельно; не повторять запись из-за отсутствия source ID среди ID доски. Создание private board из потока Save сразу сохранило выбранный пин; дополнительный Save после Create не выполнялся. См. [протокол](../../06-решения/протокол-g1-2026-11-02.md).

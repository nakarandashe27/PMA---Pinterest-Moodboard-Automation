## Правило: архитектура описывает целевую систему

Файлы архитектуры — целевой чертёж. Статусы: **реализовано** — подтверждено кодом/доказательством; **согласовано / запланировано** — решение принято, реализация может отсутствовать; **предложено / гипотеза** — уточнение механизма; **требует проверки** — результат ещё не получен. Прототип описан в ADR 0003–0010, desktop-цель — в ADR 0011; чекбоксы требуют всех критериев готовности. Согласование документа не разрешает автоматически начинать реализацию.

Для описания уже существующего поведения источником истины служит код; расхождение документации исправляется. Нарушение согласованных требований не становится допустимым только потому, что так написан код. Для запланированного/гипотезы документация задаёт целевое решение.

Значимое изменение стека, данных, границ или функций отражать в целевых файлах и новой записи [журнала решений](../06-решения/журнал-решений/2026-11-02-основа.md) с датой и причиной. Не сохранять заведомо устаревший чертёж ради формального следования плану.

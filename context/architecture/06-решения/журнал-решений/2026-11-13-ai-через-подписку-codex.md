# ADR 0013: AI в настольной PMA через подписку ChatGPT (Codex)

Дата: 2026-11-13. Статус: реализовано и проверено тестами на заглушке Codex; живая проверка на ПК владельца и ПК архитектора — см. «Что не проверено».

## Контекст

[ADR 0011](2026-11-06-десктопное-приложение.md) оставил Codex «необязательным последующим desktop-режимом» с условиями: своё обнаружение runtime, собственный вход владельца, проверка запуска, авторизацию разработчика не переносить. Архитектор поставила PMA 0.1.1, но API-ключ у неё не заработал; у неё есть подписка ChatGPT и может быть установлено приложение Codex. Подписка нужна и для анализа изображений в AI-отборе.

Прототип ([ADR 0004](2026-11-03-ai-отбор-codex-cli.md)) запускает `node %APPDATA%\npm\node_modules\@openai\codex\bin\codex.js` через `process.execPath`. В desktop `process.execPath` — Electron, а в установщике отключён fuse RunAsNode (8D.6), поэтому так запускать нельзя.

Вывод `codex login status` (исходник `codex-rs/cli/src/login.rs`): «Logged in using ChatGPT» — 0; «Not logged in» — 1; для API-ключа печатается **маскированный ключ** (первые 8 и последние 5 символов). Поэтому PMA никогда не показывает этот текст, а только классифицирует его.

Проверено на ПК владельца без вызова модели: npm-пакет 0.149.1 содержит нативный `node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\bin\codex.exe`, он отвечает на `--version` без Node. Приложение Codex из Store (26.1106) содержит `app\resources\codex.exe` в `C:\Program Files\WindowsApps\…`, но запуск из другой программы даёт «Access is denied»; псевдонима `codex.exe` в `%LOCALAPPDATA%\Microsoft\WindowsApps` нет.

## Решение

1. **Два явных режима владельца:** «Подписка ChatGPT (Codex)» и «Свой API-ключ» (по умолчанию — API, как в 0.1.1). Режим хранится на владельца (`ai-mode`), меняется только кнопкой и не вызывает модель. Исполнитель выбирается по режиму при старте шага; перехода между режимами нет ни при ошибке, ни при лимите.
2. **Обнаружение runtime** только по документированным местам, по порядку: официальный установщик `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe` → npm-пакет `%APPDATA%\npm\…\codex-win32-<arch>\vendor\<triple>\bin\codex.exe` → `codex.exe` в PATH (каталоги `WindowsApps` пропускаются). Запускается сам `codex.exe`, без Node и без `.cmd`-обёрток. Приложение Codex из Store как runtime не используется (Windows не даёт его запускать); его **вход** используется, так как каталог `%USERPROFILE%\.codex` общий.
3. **Вход выполняет человек:** в приложении Codex или кнопкой «Войти через ChatGPT», которая запускает `codex login` (браузер владельца, 10 минут). PMA не читает `~/.codex`, не вводит пароль и не переносит чужую авторизацию. Состояние — по `codex login status`: ChatGPT / нет входа / другой способ (нужен ChatGPT) / неизвестно.
4. **Вызов** — тот же исполнитель прототипа (`server/codex-selection.mjs`), теперь с явной командой запуска: `exec --ignore-user-config --ephemeral --sandbox read-only -c forced_login_method="chatgpt" -c web_search="disabled"`, отключённые shell/browser/apps/plugins/multi-agent и др., `--output-schema`, `--image`. Из окружения удаляются `OPENAI_API_KEY`, `CODEX_API_KEY`, `OPENAI_BASE_URL`, `CODEX_ACCESS_TOKEN`. Событие инструмента в ответе отклоняет результат.
5. **Учёт:** денежного резерва нет; слот месячного пула (≤100) резервируется в ledger до вызова (`currency=NULL`) и не возвращается; неизвестный результат не повторяется. Закрытый ledger закрывает и Codex-режим.
6. **Проверка:** явная кнопка «Проверить» — один вызов с красной картинкой 64×64 и строгой схемой; считается в пуле. Проверка привязана к пути найденного `codex.exe`; до неё и после смены runtime AI-шаги закрыты, ручной путь работает.

## Последствия

- Пользователю без API-ключа достаточно подписки, Codex CLI и входа через ChatGPT. Расходуется квота подписки; PMA не видит остаток квоты. Если у владельца Plus/Pro куплены кредиты, Codex может расходовать их сверх лимита — это настройка аккаунта OpenAI, PMA её не видит и не меняет.
- Список моделей берётся из `codex debug models` (команда не описана в документации; так уже работает прототип). Выбирается первая `-sol`-модель с изображениями, иначе первая доступная.
- `--ignore-user-config` пропускает и `cli_auth_credentials_store` из `config.toml`. Если владелец хранит вход в нестандартном хранилище, проверка покажет ошибку входа — это видно до работы.
- Desktop-модули: `server/ai-codex.mjs` (обнаружение, состояние, исполнитель, проверка, вход), маршруты `/api/ai/mode`, `/api/ai/codex/probe`, `/api/ai/codex/login`, UI в `src/components/AISettings.tsx`. Тесты — `server/test/ai-codex.test.mjs` на подменном `codex` (настоящий spawn, искусственные ответы).

## Что не проверено

- Живой вызов из desktop на ПК владельца и ПК архитектора; кнопка `codex login` с настоящим браузерным входом.
- Официальный установщик Codex на чистом ПК (путь `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin`) — взят из `install.ps1`, не из запуска.
- Работа read-only sandbox Windows для standalone-раскладки (в npm-раскладке прототип работал).
- Качество отбора и подготовки запроса — по-прежнему оценка архитектора.

# ADR 0008: локальная блокировка и пределы G2

Дата: 2026-11-05. Статус: реализована автоматическая часть проверки; G2 не закрыт. Пользователь подтвердил отдельный локальный пароль PMA для каждого подключения, хранение до явного удаления владельцем и общий предел до 100 AI-запусков в месяц. Дополнительно попросил предусмотреть OpenAI-compatible API для людей без подписки ChatGPT Plus.

## Изоляция

Проверка кода обнаружила: сохранённый activeConnectionId и переключатель имени открывали данные без подтверждения личности; `/media/assets` не проверял owner; ownerless G1 и общий пакет оставались доступны. Исправлены границы HTTP. Данные приложения открывает локальная сессия, принадлежащая конкретному подключению. Значение settings больше не используется как авторизация. Bootstrap без сессии отдаёт только список подключений, без проектов, файлов и паролей.

Для новых подключений пароль задаётся до открытия Chrome. Существующие профили защищает доверенный владелец Windows через интерактивный `npm run password`, при остановленном/заблокированном сервисе. Это явная первичная настройка/операторский сброс, отсутствующий в HTTP API. Пароль не отображается и не передаётся в аргументах процесса. В SQLite хранится соль и результат scrypt (N=32768, r=8, p=1); сравнение через timingSafeEqual. Источники: [Node crypto](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback), [cookie HttpOnly/SameSite](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie).

Случайная HttpOnly/SameSite=Strict cookie действует 30 минут от входа, сессия существует в памяти процесса. Один активный владелец экземпляра. Неверные пароли ограничены пятью попытками с блокировкой на пять минут; счётчик хранится в БД. Переключение, блокировка, истечение и смена хеша пароля отзывают прежний доступ и останавливают jobs/управляемые Chrome. Автоматического возобновления нет. Это логическая граница приложения, без защиты от администратора/прямого доступа к файлам той же ОС. Блокировка PMA не отзывает Pinterest cookies на внешнем сервисе.

`server/index.mjs` сохраняет запуск и восстановление. `server/app.mjs` предоставляет фабрику HTTP-сервиса для проверок с отдельной БД/портом; тесты не открывают рабочий профиль и не запускают живой экспорт. Владелец проверяется на API, media, uploads, отчётах и цепочке plugin pairing→export→attempt→snapshot→project. Исторический `/figma-package.json` отвечает 410; локальные G1-файлы сохранены. Ownerless-объекты скрыты без назначения произвольного владельца.

Живое продолжение обнаружило сетевой запрет у Chrome дочернего процесса PMA (`ERR_NETWORK_ACCESS_DENIED`) при запуске сервиса в ограниченном окружении. После разрешённого запуска с сетевым доступом отдельный чистый Chrome получил HTTP 200 от публичного Pinterest; пользовательский профиль/авторизация в пробе не использовались. Сбой открытия браузера после сохранения локального подключения теперь возвращает его ID и безопасное предупреждение вместо общей ошибки 500. UI сохраняет шаг входа и предлагает повтор в том же профиле; новый локальный пароль/дубли для повтора не нужны. Добавлен браузерный тест повторного открытия с тем же ID и неизменным числом подключений/credentials. Настройки Windows/Chrome, CAPTCHA и авторизация Pinterest не обходились.

## Figma

Код по-прежнему ограничен одной попыткой/снимком и 15 минутами; дополнительно связан с открытой сессией владельца. После входа/перезапуска надо обновить код того же набора, без создания нового фрейма. Проверка права повторяется после асинхронного чтения тела, чтобы начатый до переключения запрос не выполнил поздний claim/callback.

Квитанция требует frameId сохранённого checkpoint. Claim/checkpoint/receipt не могут переназначить его. Если Plugin API возвращает fileKey, он сохраняется и проверяется во всех шагах; пропуск известного ключа тоже конфликт. Без доступного fileKey одинаковые marker и node IDs в точной копии документа не позволяют доказать идентичность файла. Приватный API не включён, полной защиты от копирования не заявляем. Native-плагин пересобран, прежний успешный импорт не повторялся.

## AI

Один inference обычного задания и по одному на максимум три попытки замены сохраняются. Добавлен общий локальный предел 100 запусков за календарный месяц Europe/Moscow на весь экземпляр/общую подписку Codex. `PMA_AI_MONTHLY_CALLS` позволяет задать другой положительный конечный предел; неверное значение останавливает AI. Это число запусков, не деньги/токены и не размер квоты ChatGPT.

Резерв пишется через `BEGIN IMMEDIATE` до inference одновременно с состоянием AI. Конкурентные снимки одного run не получают два резерва; разные владельцы используют общий остаток. Ошибки, отмены, unknown и перезапуск не освобождают резерв. Старые callCount и сравнительные проверки учитываются консервативно один раз; унаследованные рекомендации не считают новый inference. Исходники остаются для ручного выбора при исчерпании предела. Скрипт сравнения также резервирует каждый из двух вызовов; сами сравнения в этой сессии не запускались.

## Второй режим: OpenAI-compatible API

Согласован как следующее расширение, **adapter и форма настройки ещё не реализованы**, ключи не создавались, сетевые inference не выполнялись. Текущий `rankCandidates` уже отделяет детерминированные prompt/schema/валидацию от `invoke`; эту границу надо сохранить для второго исполнителя.

Требования расширения: выбор владельцем `codex-chatgpt` либо `openai-compatible`, собственные endpoint/model/ключ и возможности мультимодального JSON-ответа. Не предполагать совместимость по одному имени протокола: проверять передачу изображений, схему и usage для конкретного endpoint. Ошибка CLI не переключает задачу на платный API. Ключ относится к подтверждённому владельцу и хранится на стороне сервиса, отсутствует в bootstrap, модели, логах и пакетах Figma. Endpoint проверяется как внешний HTTPS-адрес; доступ к loopback/служебным адресам и произвольные redirect не разрешаются по полю URL.

Для API сохраняется предел 100 inference и дополнительно нужен настроенный конечный денежный/токенный бюджет с атомарным верхним резервом до вызова. Цена/тарификация неизвестного провайдера не выдумываются. Таймаут/отмена сохраняют резерв; inference unknown не повторяется. Смена провайдера/модели/endpoint фиксируется в версии запуска и не передаёт старые задачи другому владельцу. До отдельной настройки эти требования не считаются готовым режимом работы по API.

## Хранение

Хранить завершённые проекты, примеры, изображения, промежуточные результаты и квитанции до явного локального удаления владельцем. Автоматического TTL и фоновой очистки нет. Pending/paused/unknown и необходимые им файлы сохранять; инвалидность кода или отключение подключения не удаляет данные.

Пользовательское удаление и безопасная очистка файлов ещё не реализованы. При реализации проверять активные ссылки и общие SHA-assets, сохранять счётчики расхода, отдельно подтверждать локальную область удаления. Локальное удаление не удаляет доски/пины/фреймы Pinterest/Figma. Общий сервер и корпоративные сроки/backup остаются отдельным решением.

## Проверки

Последующее живое испытание выхода A: новый run без AI остановился до карточек и сохранил owner A. Исправлен переход утраты username в `blocked/login` с явным продолжением и добавлены проверки личности до/после каждой порции. Пять новых тестов, общий итог 122 passed; live-run восстановлен в паузу при штатном перезапуске. Повторный ручной вход/продолжение этого же run ещё ожидается. [ADR 0010](2026-11-05-восстановление-pinterest-входа.md).

Живые два аккаунта подтверждены: B имеет другой Pinterest username и видит только свой новый локальный тестовый проект. В его авторизованной вкладке известные A project/export/upload/report вернули отказы, A asset не отдался. Штатная блокировка убрала проект B с экрана, отозвала доступ к его API и закрыла Chrome B (0 процессов соответствующего профиля). После ручного входа A вернулись три прежних проекта; B project закрыт. A открыл тот же asset, историю/выбор из семи и прежнюю квитанцию Pinterest succeeded 7/7 + Figma imported `30:2`. Открытие и повторная проверка служебного профиля A подтвердили исходную Pinterest-личность. Завершённые экспорты и AI-вызовы не запускались. Браузерные свидетельства — тела реальных ответов/состояние UI, числовые HTTP-статусы инструментом не извлекались.

В отдельном тестовом проекте A подготовлен запрос без AI; ожидается ручной выход владельца из Pinterest перед запуском, затем проверка остановки/owner и восстановления. Проверка переключения во время активного задания также ещё открыта. Общий G2 остаётся открытым; проверенная изоляция чтения не закрывает эти сценарии и ограничение копий Figma без fileKey.

Полный `npm test`: 122 тестов прошли. `npm run build` и `node scripts/build-plugin.mjs` прошли, синтаксис entrypoint/CLI проверен. Браузерный тест собранного приложения проверил неверный/верный пароль, смену A→B, блокировку и очистку второй вкладки, новый профиль с сохранением ручного шага Pinterest, viewport 390×844. Исключений страницы нет. На просмотренном мобильном screenshot укорочена слишком длинная кнопка создания подключения; итоговая сборка/браузерная проверка повторены после этой правки.

[Матрица и ручные шаги G2](../протокол-g2-2026-11-05.md) отличают HTTP/браузерные тесты с временными владельцами от ещё не проведённой проверки второго настоящего Pinterest-аккаунта. Пользователь выполнил `npm run password`, присланный скриншот подтвердил установку. Агент затем проверил принадлежность старого процесса проекту и отсутствие активных jobs, перезапустил сервис и подтвердил реальные анонимные отказы API/media/G1; контрольная сумма экспортных записей не изменилась. Две старые записи оказались одним Pinterest username. Пользователь подтвердил наличие другого настоящего логина; две новые waiting-записи созданы до сетевого сбоя, пока без Pinterest identity. После исправления выбран последний сохранённый профиль, его ручная разблокировка и вход B ещё ожидаются. Секреты не запрашивались и не переносились в контекст.

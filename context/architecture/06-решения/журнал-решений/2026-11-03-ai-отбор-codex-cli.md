# ADR 0004: проверка визуального отбора через Codex CLI

Дата: 2026-11-03. Статус: проверочный сценарий реализован; автоматический отбор в обычном поиске и качество для пилота ещё не подтверждены.

Последующее изменение того же дня: необязательный отбор подключён к пользовательскому поиску — [ADR 0005](2026-11-03-ai-отбор-в-поиске.md). Ниже сохранён протокол исходного отдельного сравнения; он не является экспертной оценкой качества.

## Решение и доступ

Пользователь выбрал Codex CLI с авторизацией через ChatGPT вместо настройки отдельного API-ключа. На ПК установлен codex-cli 0.149.1; пользователь завершил штатный вход. Официально [CLI поддерживает доступ по подписке](https://learn.chatgpt.com/docs/auth), а [codex exec](https://learn.chatgpt.com/docs/non-interactive-mode) — изображения, сохранённую авторизацию и структурированный ответ.

Эксперимент запускает два последовательных процесса CLI: оценку по исходному фото и оценку по тому же фото с текстом/пояснением. Входной пул, порядок и schema одинаковы. Максимум 50 кандидатов, 24 МиБ суммарных изображений, 180 секунд на процесс, 3 МиБ stdout. Платный API-fallback и автоматический повтор отсутствуют. Это ограничение числа/длительности процессов, а не гарантия конкретной доли квоты подписки или долларового расхода. Глобальный месячный бюджет для будущего сервиса не реализован.

Worker использует ChatGPT-auth принудительно, read-only sandbox, изолированный рабочий каталог и отключённые shell, browser, plugins, apps и multi-agent. Ключи API удаляются из окружения дочернего процесса. Токены авторизации не читаются приложением и не копируются в проект. Содержимое изображений и подписи не дают права вызывать инструменты.

## Модель и воспроизводимость

Попытка GPT-6.1-Sol была отклонена сервером model_not_found до получения оценки. Каталог установленного CLI отличался от каталога desktop-приложения. Повторная проверка выполнена на GPT-5.6-Sol, полученной из актуального `codex debug models`. Наличие в каталоге — предварительная проверка; только успешный inference подтверждает доступ. CLI не обновлялся, токены из desktop-приложения не извлекались.

Скрипт [evaluate-selection.mjs](../../../../scripts/evaluate-selection.mjs) принимает ID двух готовых Lens/text-подборок одного проекта и активного владельца. Сохраняет неизменный входной manifest с pin ID/URL, SHA-256, ID источников и исходного фото. Кандидаты дедуплицируются по pin ID и точному SHA, файлы проверяются и копируются в отдельный каталог эксперимента. Модель получает изображения и короткие ID, исходные ссылки восстанавливаются из manifest.

Ответ обязан оценить каждый ID ровно один раз. Посторонние/повторные/пропущенные ID и некорректные баллы отклоняются. Порядковые оценки 0..4 не являются вероятностью или измеренной точностью. Отбираются кандидаты с баллом от 3 и достаточным визуальным основанием; явно отмеченные моделью почти одинаковые кадры ограничиваются одним представителем. Исходные кандидаты и ручной выбор сохраняются.

## Результат первого кейса

Один пример: связь модернистской/бруталистской архитектуры с японскими мотивами сада. Пул — 25 ранее полученных Lens-кандидатов и 25 текстовых кандидатов того же проекта.

| Условие | Отобрано | Время процесса | Входные токены | Выходные токены |
|---|---:|---:|---:|---:|
| Только исходное фото | 21 | 90,699 с | 19 930 | 4 289 |
| Фото + текст и пояснение | 23 | 62,785 с | 19 955 | 4 497 |

Общих кандидатов — 18. В варианте с текстом добавились пять садовых референсов и не вошли три преимущественно архитектурных. Часть добавленных садов не показывает связь со зданием; пригодность такого баланса должен оценить архитектор. По одному запуску на условие нельзя отделить влияние текста от вариативности модели. Нет ручной разметки, оценки точности, доказанной экономии времени или сравнения нескольких моделей. Число токенов не определяет процент оставшейся квоты подписки.

Результаты, prompts, responses и события CLI сохраняются в ignored `.local/pma/evaluations/`. Страница сравнения доступна только локально и после проверки владельца проекта; содержит исходные пины, контрольную/совместную подборки и полный пул с баллами. В основном интерфейсе есть ссылка у соответствующих исходных подборок. Никакой автоматической записи в Pinterest/Figma этот эксперимент не выполняет.

## Следующие проверки

Архитектор оценивает подборки на одинаковом пуле; затем нужны несколько разных брифов, перестановка кандидатов/повторы, приоритет обязательных признаков и проверка недобора/дублей. После этого — отдельное включение отбора в пользовательский запуск с видимыми лимитами и отменой. На ПК архитектора нужен её штатный вход Codex; модель доступа для общего сервера проектируется отдельно.

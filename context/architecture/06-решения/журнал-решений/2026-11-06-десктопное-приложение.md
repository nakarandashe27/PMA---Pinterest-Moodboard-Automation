# ADR 0011: самостоятельное десктопное PMA для пилота

Дата: 2026-11-06. **Статус: архитектура и план обновления контекста согласованы пользователем; desktop-код, установщик и API-режим не реализованы.** Реализация начинается отдельным поручением.

## Контекст

Локальный прототип уже выполняет Pinterest-поиск/Lens, подготовку запроса из замысла через Codex CLI, необязательный AI-отбор, ручной выбор, замены и два независимых экспорта. Последний зафиксированный результат — 141 успешный тест и production-build, а не результат повторного запуска в этой сессии. Pinterest 7/7 и native-фрейм Figma 30:2 подтверждены ранее; повторять их ради упаковки не нужно. Источники: [передача](../../../HANDOFF.md), [ADR 0007](2026-11-05-независимые-экспорты.md), [ADR 0009](2026-11-05-замысел-в-поисковый-запрос.md).

Передача исходников не удовлетворяет самостоятельному запуску: [entrypoint](../../../../server/index.mjs) привязан к workspace/.local/pma, [AI-исполнитель](../../../../server/codex-selection.mjs) — к npm-пути Codex и process.execPath, [плагин](../../../../spikes/figma-g1/plugin/ui.template.html) — к localhost:8787. Установка одной UI-оболочки эти зависимости не устраняет.

## Подтверждено интервью

| Решение | Согласованный результат |
|---|---|
| ОС архитектора | Вероятно Windows 10; точные build/разрядность ещё не проверены |
| Установка | Обычный установщик; права администратора доступны |
| AI первого релиза | Собственный API-ключ; подписка ChatGPT и Codex CLI не обязательны |
| Провайдер | Настраиваемые endpoint/model/key без привязки к одному OpenAI-compatible провайдеру |
| Бюджет | Владелец задаёт месячный денежный предел и тариф модели в PMA; до настройки платный AI выключен |
| Браузер | Установленный Google Chrome; отдельный persistent-профиль PMA, диагностика отсутствия |
| Крестик окна | Завершает приложение и управляемые операции/Chrome; данные сохраняются, продолжение явное |
| Обновления | Вручную новым установщиком; данные сохраняются, перед миграцией создаётся backup |
| Первый запуск | Допустима разовая совместная настройка API, бюджета и Figma-плагина; затем самостоятельная работа |

Общий предел пилота — до 100 inference за календарный месяц Europe/Moscow. Данные остаются до явного удаления владельцем. Эти прежние продуктовые решения сохраняются; денежный бюджет дополняет счётчик вызовов.

## Решение

1. **Electron, React renderer и отдельный backend utilityProcess.** Доменную логику Node/SQLite/Playwright сохраняем. Версию Electron выбираем из поддерживаемой стабильной ветки с проверенным Node 24.x и node:sqlite; квалификация упакованного runtime обязательна.
2. **Локальный UI и ограниченный IPC.** Renderer загружает только поставленные ресурсы через app://pma, работает с sandbox/contextIsolation и без Node integration. Preload предоставляет фиксированные операции с ограниченными DTO. Main проверяет sender/frame и связывается с worker через MessagePort. Валидация, owner, сессия, revision и бюджет находятся в общем backend dispatcher для desktop и dev HTTP.
3. **Loopback только для Figma.** В desktop-режиме 127.0.0.1:8787 обслуживает ограниченные Figma-маршруты. Обычные bootstrap/account/API/media/report через этот listener недоступны. Занятый порт — диагностический отказ; чужой процесс не останавливается и не используется.
4. **Один экземпляр и управляемое завершение.** Lock до открытия БД/миграций/recovery; второй запуск фокусирует окно. Shutdown имеет конечный срок, сохраняет незавершённое и завершает только принадлежащие PMA процессы. Падение и перезапуск не разрешают скрытый inference или повтор внешней записи.
5. **Данные вне установки.** Стабильный корень %LOCALAPPDATA%/PMA, отдельные данные, профили, учёт расходов, диагностические записи и интеграция Figma. API-ключи защищаются Windows vault/DPAPI через узкий сервис секретов. Полного шифрования проектных файлов и защиты от программ той же Windows-учётной записи не заявляем.
6. **API-адаптер вместо обязательного CLI для архитектора.** Настраиваемые профили, явный выбор модели и проверка возможностей. Общие wire formats Responses/Chat Completions — инженерное решение; поддержка изображений, структуры, usage и тарификации подтверждается для конкретного профиля. Автоматических model/provider fallback и retry неизвестного вызова нет.
7. **Денежный резерв и непрерывность учёта.** До inference атомарно резервируются вызов и доказанная верхняя оценка стоимости. Учёт не откатывается вместе с проектной БД при restore. Неизвестная тарификация или утрата актуального ledger блокируют платный AI до сверки.
8. **Обычный Windows-установщик и ручные обновления.** Предлагаемый сборочный инструмент — стабильный electron-builder/NSIS. Готовый development-плагин Figma находится в стабильной папке; импорт и запуск выполняются явно. Подпись/доверенный канал передачи — открытый выпускной gate, а не выполненная публикация.

Подробный контракт: [desktop-архитектура](../../05-стек/десктопное-приложение.md). Сценарий владельца: [первый запуск](../../04-потоки/первый-запуск-десктопа.md).

## Альтернативы и последствия

| Вариант | Повторное использование и поставка | Причина решения |
|---|---|---|
| Electron + utilityProcess | React и backend сохраняются; Chromium/Node идут с приложением, Chrome Pinterest остаётся внешним | Выбран: меньше новых связующих слоёв, готовые средства окна/IPC/секретов |
| Tauri + Node-sidecar | React/backend сохраняются; Node нужно поставлять отдельно, Windows UI использует WebView2; сборка добавляет Rust | Уместная альтернатива, но размер оболочки не оправдывает дополнительную интеграцию для этого пилота |
| Electron + отдельный поставляемый Node | Сохраняет обычный Node-процесс, но дублирует runtime и его сопровождение | Резервная гипотеза, если квалификация utilityProcess провалится; переход требует обновления ADR |

IPC требует извлечь транспорт из app.mjs и адаптировать api.ts/media, но сохраняет бизнес-операции и их проверки. От UI на loopback с автоматически добавляемым instance-secret отказались после premortem: origin не удостоверяет процесс, занявший порт после аварии. Системный Chrome, Figma Desktop, сеть и ключ владельца остаются явными внешними зависимостями.

## Что сохраняем из прежних решений

Pinterest — единственный источник; Lens не подменяется текстом. Поиск подтверждается отдельно от интерпретации. AI получает только разрешённый текст/изображения, без инструментов, браузерной авторизации и права экспорта. Окончательный выбор остаётся у архитектора. Owner/snapshot/attempt неизменны; поздний callback не переносится в новую сессию. Два экспорта независимы; unknown сначала сверяется, ручные правки и исторические квитанции сохраняются.

Рабочий Codex-код не удаляется. Его последующее необязательное desktop-подключение реализовано в [ADR 0013](2026-11-13-ai-через-подписку-codex.md); оно требует отдельного обнаружения runtime, собственного входа владельца и проверки запуска; текущую авторизацию разработчика не переносим. [ADR 0008](2026-11-05-изоляция-и-пределы-g2.md) и [ADR 0010](2026-11-05-восстановление-pinterest-входа.md) сохраняют историю.

## Открытые проверки

- Windows 10 не объявлена безусловно поддерживаемой: актуальная матрица Playwright указывает Windows 11+. Здесь read-only проверкой .NET установлены Windows 10.0.19045 и X64; это сведения о ПК инициатора, не архитектора.
- Нужны установленный пакет на чистом ПК, node:sqlite/Playwright в utilityProcess, отсутствие осиротевших Chrome и проверенная связь Figma.
- Нужны конкретный API-профиль, доступность/оплата в рабочей сети, billing mapping, тариф и бюджет; ключи в этой сессии не создавались.
- Точная копия Figma без доступного fileKey остаётся ограничением. Нужны оставшиеся живые сценарии G2, перенос/G3 и оценка реальных брифов.
- Подпись, доверенная передача и ответственность за доставку критических ручных обновлений уточняются до распространения.

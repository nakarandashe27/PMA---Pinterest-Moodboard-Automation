# ADR 0007: независимые экспорты одного снимка выбора

Дата: 2026-11-05. Статус: реализовано и проверено локально; оба назначения подтверждены на одном наборе из семи изображений. Этап 7 закрыт, G1/G2/G3 целиком не закрыты.

## Решение

«Экспорт выбранного» создаёт неизменяемый снимок до 25 изображений: исходный аккаунт/проект, порядок, исходные Pinterest ID/URL, SHA и файлы. Два назначения используют этот снимок, но имеют независимые состояния и квитанции. Последующая правка выбора или замена кадра не изменяет ранее подготовленный пакет. Все большие Pinterest ID остаются строками.

Подготовка не выполняет внешних записей. Pinterest-save запускается отдельно; Figma требует явного запуска development-плагина. Нет распределённой транзакции или удаления успешного результата другого назначения при сбое.

## Pinterest

Адаптер использует видимый DOM обычного Pinterest в отдельном профиле приложения. Проверяет активный аккаунт, точную доску, владельца и видимый признак SECRET. Одна доска связывается с проектом; после привязки её URL неизменен. Название не длиннее 50 UTF-16 единиц, содержит суффикс проекта; обрезка не разрывает суррогатную пару. Слишком длинное ручное название отклоняется до открытия браузера/резерва записи.

Создание доски из Save сохраняет первый пин. Перед каждой мутацией пишется durable-резерв unknown; последующая сверка читает доску и сопоставляет видимый ключ изображения с исходником. Квитанция различает sourcePinId/savedPinId. Полнота чтения подтверждается видимым числом пинов и собранными карточками доски; рекомендации не учитываются. Доски более 500 пинов или неполная выдача не объявляются проверенными.

После таймаута, отмены или перезапуска сначала выполняется readback. Неизвестный отсутствующий пин автоматически не сохраняется снова. Ранее проверенный, но вручную удалённый пин даёт конфликт. При задержке выдачи разрешены три чтения с паузой 600 мс, без повторения Save. Успешное чтение может разрешить продолжение только оставшихся pending-пинов.

## Figma

Пакет v2 содержит attempt, snapshotHash и SHA исходных файлов. Код соединения действует 15 минут, хранится в сервисе только хешем и открывает одну попытку. Обновление кода не перепривязывает старые callback к новой попытке. Сервис выдаёт эксклюзивную аренду на 120 секунд. Плагин фиксирует ID созданного фрейма до построения содержимого и хранит метки попытки/снимка и ожидаемую структуру узлов.

Плагин проверяет байты до преобразования WebP, затем создаёт отдельные изображения и текстовые ссылки. Повтор сверяет состав, порядок, геометрию, подписи, исходные URL и image hashes; догружает только отсутствующие изображения в неизменённых узлах. Завершённый фрейм возвращает квитанцию без дубля. Ручные изменения, удаление, потеря меток, неполное построение структуры или неоднозначный legacy-фрейм дают конфликт. Новый отдельный импорт разрешён явным действием, максимум три попытки на снимок. Старые фреймы не переписываются.

Сервис принимает успешную квитанцию только со всем упорядоченным набором исходников/SHA и непересекающимися ID изображений/ссылок. Поздний callback остаётся в своей попытке. Последующий конфликт не уничтожает историческую успешную квитанцию.

Локальный document marker не является глобально достоверным fileKey и копируется вместе с документом. Приватный Plugin API не включён. Изоляция и перенос на другой аккаунт/ПК остаются G2; полноценная серверная схема доступа здесь не решена.

## Проверка и исправления

98 автоматических тестов проходят. Новые проверки покрывают неизменяемые пакеты, конкурентную подготовку, повреждение asset, аренду/полноту квитанции Figma, поздний ответ, сохранение исторического успеха, явную новую попытку, partial/unknown и повторное чтение Pinterest, неверного владельца/публичную доску, ручное удаление, ограничение имени и подтверждённый отказ формы. Семь тестов native-совместимого ядра выполняют реальное ядро раскладки с макетом Plugin API; это не доказательство native-запуска.

Живая проверка Pinterest выполнена на согласованном наборе из семи изображений, включая применённую точечную замену. Первоначально Pinterest отклонил имя доски: 51 символ при лимите 50. Скриншот пользователя однозначно показал отказ формы. Исправлен генератор, добавлена проверка формы до резерва и тесты. Один конкретный отказ восстановлен операторской процедурой с неизменяемой записью доказательства и SHA скриншота; это не общий сброс unknown и не пользовательский API. Итоговое имя содержит 46 символов.

После создания проверены владелец и SECRET. На четвёртом пине Pinterest показал неполную выдачу: сохранение не повторялось, отдельное чтение подтвердило четыре пина. Затем добавлены ограниченные повторные чтения, продолжены только три pending-пина. Итог: семь из семи сверены на одной секретной доске; unknown отсутствуют. Приватные URL доски, аккаунт и квитанции остаются в локальной БД.

Обновлённое окно native-плагина открыто пользователем; Computer Use прочитал поля и вставил код. Клики и захват окна недоступны, поэтому загрузка/импорт переданы пользователю. Во время ожидания истёк 15-минутный код, он обновлён для той же попытки. Следующая живая загрузка выявила отсутствие `crypto.subtle` в UI sandbox: `Cannot read properties of undefined (reading 'digest')`. Сверка остановилась до native-import.

Web Crypto заменён переносимой SHA-256 без внешних библиотек и ослабления проверки asset. Функция проверена на стандартных векторах, миллионе байтов, Unicode и границах блоков сравнением с Node crypto. Собранный UI выполняется в браузерных тестах без `crypto`: корректный файл достигает native-inspect, изменённый отклоняется до него. `ui.html` теперь генерируется из `ui.template.html` и `sha256.mjs` командой сборки плагина. Пользователь перезапустил окно плагина со свежим кодом. Старые native/коннекторные фреймы не служат доказательством нового импорта.

Следующий живой запуск дошёл до таймаута native-inspect, сервис остался prepared без аренды создания фрейма. Выявлена некорректная проверка `event.source === parent`: UI Figma может получать пересланные сообщения. Тесты со вложенным relay-окном и synthetic MessageEvent воспроизвели зависание, после исправления проходят. Ответы и checkpoint теперь связываются с экземпляром UI через channel и requestId, без предположения об уровне iframe. Проверяются также игнорирование постороннего channel и корректная native-обработка checkpoint. Пользователь видит отдельный прогресс получения пакета, проверки изображений и сверки с файлом.

Контракт обмена проверен по [официальной инструкции Figma](https://developers.figma.com/docs/plugins/creating-ui/#sending-messages-between-the-ui-and-plugin-code) и [figma.ui.postMessage](https://developers.figma.com/docs/plugins/api/properties/figma-ui-postmessage/) 2026-11-05: UI получает данные через `event.data.pluginMessage`; принадлежность ответа непосредственному parent не является заявленной частью контракта.

## Итог живой проверки

После исправлений пользователь загрузил пакет и создал native-фрейм 30:2 в тестовом Design-файле. PMA получил полную квитанцию, состояние imported, попытка одна. Независимое чтение через коннектор подтвердило семь image fills, семь исходных Pinterest URL и 32 отдельных узла-потомка; ID узлов и image hashes совпали с native-квитанцией для каждого выбранного источника, включая применённую замену. Проверен screenshot: изображения и отдельные подписи/ссылки видимы, перекрытий нет. Размер фрейма 1776×868.

Пользователь повторно нажал только «Загрузить и сверить подборку»: плагин сообщил, что изображения/ссылки сверены, набор уже есть, дубликат не создан, фрейм 30:2. Повторное независимое чтение подтвердило ровно шесть верхних фреймов: прежние пять плюс только 30:2. Прежние фреймы сохранены. Приватные квитанции и runtime-файлы остаются локально.

Окно PMA независимо показывает Pinterest succeeded (7/7) и Figma imported (30:2); ошибок/warn в консоли нет. До этого проверены обычный и узкий viewport 390×844. Все 98 тестов проходят; TypeScript/production-сборка прошла до последних изменений только в плагине, сборка плагина и браузерные тесты его итогового UI выполнены отдельно. Это подтверждение локального сценария экспорта, а не постоянной доступности Pinterest, изоляции второго аккаунта, переноса или самостоятельного пилота.

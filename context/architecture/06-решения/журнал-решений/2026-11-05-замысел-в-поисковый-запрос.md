# ADR 0009: свободный замысел → поисковая формулировка

Дата: 2026-11-05. Статус: реализовано и технически проверено локально по прямому поручению пользователя. Есть реальный текстовый запуск Codex CLI; экспертная оценка на настоящих брифах архитектора и полезность Pinterest-выдачи ещё впереди. G2/пилот этим изменением не закрываются.

## Задача

Архитектор часто описывает желаемый образ, атмосферу и впечатление свободным текстом. Он не обязан заранее знать несколько точных Pinterest-ключей. Предположение интервью Q1 о достаточности короткого запроса сохраняется как историческое; новый основной сценарий дополнительно принимает описание замысла и готовит из него пригодную поисковую формулировку.

Пользователь отдельно сформулировал принцип: использовать AI там, где он приносит пользу; избегать избыточного AI и применения ради самого AI.

## Принятая продуктовая граница

Свободное описание → короткая интерпретация → конкретный Pinterest-запрос → подтверждение/правка архитектором → существующий детерминированный поиск. Образ, обязательные/нежелательные признаки, предположения и поисковая формулировка различаются. Архитектор проверяет, правильно ли понят замысел; владение поисковыми ключами не является условием использования инструмента.

Например, «Хочу тихий камерный двор, много зелени, ощущение уединения, без парадности» может превратиться в «уединённый зелёный внутренний двор ландшафтный дизайн». Материал, тип мощения, климат, виды растений или японская стилистика не добавляются как требования без основания в исходном описании. При существенной неоднозначности — одно содержательное уточнение, не серия вопросов на каждый эпитет.

Готовые точные слова и каноническая ссылка на Pinterest-пин могут идти прямо в поиск. Нативный Pinterest Lens остаётся визуальным механизмом: описание изображения не заменяет его текстовым поиском. Финальный ручной выбор сохраняется при любом использовании AI.

## Реализованный UX

Реализованная форма и границы:

- Основное поле «Опишите, что хотите увидеть» принимает обычное описание, включая несколько предложений. Отдельный простой путь «У меня готов поисковый запрос» позволяет пропустить AI.
- Явное действие «Подготовить поиск» вызывает интерпретацию один раз. Ответ показывает краткое «Что ищем» и редактируемый основной запрос. Не заставлять архитектора выбирать из длинного списка синонимов.
- При пользе допускаются до двух альтернативных формулировок. Поиск выполняется только по подтверждённой формулировке; несколько автоматических поисков этим решением не включаются.
- Нет фоновых inference на каждое нажатие клавиши. Неизменившийся подтверждённый бриф использует сохранённую интерпретацию в пределах того же владельца/версии/модели.
- При недоступном AI сохраняются текст и черновик; остаётся ручной поиск. Ошибка не меняет источник и не переключает пользователя на платный API автоматически.
- «Сохранённые описания» возвращают до восьми последних подготовок текущего владельца/проекта, включая готовую формулировку и незавершённые состояния. Открытие сохранённого результата не вызывает модель. Введённый ответ на существенное уточнение создаёт новую явно оплачиваемую локальную версию; после него повторный вопрос не принимается.
- В чистом Lens без AI-отбора текстовая подготовка пропускается: фото идёт напрямую в Lens. При Lens + отборе AI-подготовка может сформулировать только дополнительный текст, не анализируя сами фотографии.

## Где AI нужен

| Шаг | Роль AI | Обычный код / человек |
|---|---|---|
| Свободное описание | Понять смысл и подготовить короткую поисковую формулировку | Хранение версии, схема ответа, подтверждение архитектора |
| Конкретный готовый запрос / pin URL | Пропускается; помощь остаётся доступной по необходимости | Проверка ссылки, запуск поиска |
| Соответствие картинок замыслу | Необязательная семантическая оценка найденных изображений | Исходники сохраняются, финальный выбор архитектора |
| Авторизация / owner / лимиты | Не используется | Детерминированные проверки сервиса |
| Загрузка / точные дубли / сохранение выбора | Не используется | Проверка байтов, SHA, IDs и revisions |
| Экспорт / квитанции / сверка | Не используется как исполнитель | Явные действия, детерминированный adapter и Plugin API |

## Реализация и пределы

Используется уже согласованный Codex CLI и существующий ChatGPT-вход, без нового API-ключа. В живом тесте модель `gpt-5.6-sol` выбрана из доступного CLI-каталога. OpenAI-compatible API остаётся отдельным запланированным режимом ADR 0008. Модель фиксируется в версии подготовки; при повторном открытии готовый результат не переоценивается новой моделью.

Интерпретация получает только разрешённый контекст брифа и не получает browser tools, Pinterest-сессию, назначения экспорта или право запускать поиск. Ответ валидируется как структурированные данные, а не команда инструментам. Выделение понятий не даёт права переопределить смысл запроса или выдумать факты об изображении.

Inference интерпретации — отдельный явно учитываемый вызов: он входит в общий предел до 100 запусков/месяц вместе с отбором и заменами. Резерв должен быть атомарным до вызова, привязанным к владельцу и версии брифа. Unknown не повторяется автоматически. Для API дополнительно нужен настроенный денежный/токенный предел; изменение месячного лимита данным решением не согласовано.

Реализация: `interpretation` хранит неизменяемые owner/project/input/promptVersion и выбранную модель; ключ включает текст, пояснение, режим, ID собственных примеров и ответ на уточнение. Переходы `queued → preparing → running → ready/error/unknown/cancelled`; перезапуск переводит начатый inference в unknown, а этап без вызова — в interrupted. Атомарный claim исключает конкурентные inference одной версии. Перед invoke используется общий `ai-reservation`; таймаут подготовки 90 секунд. Отмена/блокировка владельца останавливает worker, поздний ответ не становится готовой формулировкой для B.

HTTP: POST `/api/interpretations`, GET `/api/interpretations/:id`, POST `.../:id/cancel`, GET `/api/projects/:id/interpretations`. Все маршруты проверяют активную сессию и owner проекта. Поиск запускается отдельным POST `/api/runs`: он проверяет принадлежность готовой подготовки и точное совпадение исходной версии, отсутствие неразрешённого уточнения; редактировать подтверждаемую поисковую формулировку человеку разрешено. История сохраняет исходное описание, принятую формулировку, краткое понимание и происхождение AI; дочерняя замена сохраняет эту связь. Сервер не выдаёт подготовку, список или cancel другого владельца.

## Технические доказательства

Полный `npm test`: 141 тест прошёл, включая 19 проверок нового шага. Проверены схема/размеры/неизвестные поля ответа, запрет ссылок вместо поисковых слов, один вопрос, изменения версии, конкурентный claim/резерв, общий месячный предел, unknown/restart/cancel, поздний ответ, owner/project/uploads, неизменяемость входа и подтверждение перед поиском. Собранная форма проверена в Chrome на обычном и узком экране: подготовка без поиска, правка запроса, повтор без inference, ready-query/pin URL без AI, уточнение, ручной путь при ошибке, отмена при закрытии, чистый Lens и восстановление сохранённого описания. Скриншоты — вне репозитория, в каталоге visualizations текущего чата. Production-build прошла. Обновлённый localhost-сервис штатно перезапущен после проверки отсутствия активных операций.

Один реальный inference выполнен на обезличенном примере из этого ADR с пояснением о реальных ландшафтных референсах. Получен основной запрос «камерный зелёный двор уединённый ландшафт», две альтернативы, четыре желательных признака и «парадность» среди нежелательных; assumptions и clarification пусты. Использована `gpt-5.6-sol`: 9 762 input tokens и 116 output tokens по отчёту CLI. Это измерение одного вызова, не денежная цена и не размер подписочной квоты. Резерв ровно один, повтор входа вернул тот же ID, событий инструментов 0. Pinterest-поиск, AI-отбор изображений и внешние экспорты при этой пробе не выполнялись. Квитанции прежних экспортов сохранили ту же контрольную сумму.

## Критерий полезности

На нескольких настоящих описаниях главного архитектора проверить сохранение замысла, понятность предложенной формулировки, необходимость правок и полезность Pinterest-выдачи. Сравнить с готовым коротким запросом, для которого AI должен пропускаться. Успешная JSON-схема или красивое перефразирование сами по себе не доказывают пользу. Один технический живой пример и браузерные тесты этого экспертного испытания не заменяют.

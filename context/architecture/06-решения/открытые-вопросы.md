# Открытые технические вопросы

Статус: известные пробелы, а не скрытые предположения. Некоторые механизмы уже подтверждены на одном аккаунте в [практической пробе](протокол-g1-2026-11-02.md); это не закрывает переносимость и production-доступ. Подтверждённые продуктовые решения не переоткрываются.

Обновлено 2026-11-06: [ADR 0011](журнал-решений/2026-11-06-десктопное-приложение.md) закрепил desktop-поставку и API первого релиза. Повторно не спрашивать выбор источника, двух экспортов, локального пароля, хранения до удаления, установленного Chrome, выхода крестиком, ручных обновлений или совместной первой настройки. Два настоящих аккаунта и прежние экспорты уже подтверждены; текущие остатки G2 — в [матрице](протокол-g2-2026-11-05.md).

| Вопрос | Кто/как закрывает | Когда |
|---|---|---|

| OAuth Trial/Standard, независимый аккаунт, secret scopes, видимость результата | Отдельные проверки API/подключения | До обещания поддерживаемых аккаунтов |

| Живое продолжение Pinterest A после входа и смена активного задания | Существующие identity/password/изоляцию двух аккаунтов не переоткрывать; завершить оставшиеся сценарии G2 | До допуска к самостоятельному пилоту |
| Поставка Figma-плагина, stable path/protocol и работа на целевом ПК | Локальный native-import/retry уже подтверждён; desktop D8–D9/D20. Ограничение точной копии без fileKey сохраняется | До передачи пилота |
| Конкретный API-профиль, рабочая сеть/оплата, качество и billing mapping | Настраиваемый provider уже выбран как принцип; проверить реальный endpoint/model и тариф владельца | До платного использования |
| Денежный предел и верхняя стоимость запроса | Общие 100 inference и отсутствие hidden retry согласованы; сумма/тариф задаются в настройках до запуска, ledger/restore проверяются | До самостоятельного пилота |

| Упакованные Node/SQLite/Playwright и Chrome на другом ПК | Runtime-проба D0–D2; Python/Docker не являются зависимостями выбранного desktop-решения | Перед переносом |
| Пять реальных задач и исходное ручное время | Главный архитектор в пилоте | После работоспособной цепочки |
| Дата запуска, ответственные контакты, бюджет и имя бюро | Пользователь/бюро при необходимости | Не блокирует документацию |
| Сервер, параллельные пользователи, корпоративный вход и политика данных | Отдельное серверное проектирование | После локального пилота |

## Выпускные вопросы desktop

| Неизвестное / проверка | Как закрывается |
|---|---|
| Точная Windows/build/x64 архитектора | Проверка её ПК; текущий ПК инициатора — Windows10.0.19045/X64. Windows10 не объявлена upstream-supported Playwright |
| SQLite/ESM/Playwright в utilityProcess и ресурсах installer | D1–D2, включая чистое окружение без Node/npm/Codex |
| Перенос авторизации HTTP в IPC и приватных media | Единые backend-проверки, session generation и отрицательные D4–D9; не выдавать UI доверенный owner |
| Supervisor/закрытие/аварийное дерево Chrome | Конечный протокол и D10–D11, только принадлежащие PMA процессы |
| Схемы, технический backup/restore и непрерывность ledger | D17–D19/D21; при утрате актуального учёта платный AI закрыт до сверки |
| Доверенная передача и подпись installer, критические обновления | Определить до распространения, затем D24; не покупать сертификат и не публиковать автоматически |
| Локальная операторская процедура забытого пароля | Проверить поставляемый способ, без HTTP-reset и npm-инструкции для архитектора |
| Разовый импорт плагина/сеть на её аккаунте | Совместная настройка допустима; затем самостоятельный сценарий и D20 |

План — [desktop-приёмка](приёмка-десктопа.md), механизмы — [архитектура](../05-стек/десктопное-приложение.md). Автоматический перенос developer .local/pma/авторизаций не входит в поставку; перенос проектных данных требует отдельного согласования.

Изменение роли Lens, источника, результата Figma или подтверждения выбора обсуждать явно. Если информации нет, статус остаётся гипотезой; неизвестное не заполняется вымышленными цифрами.

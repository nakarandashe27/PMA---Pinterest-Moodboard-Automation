# Первый технический этап: проверка интеграций

Статус: план экспериментов частично выполнен; фактические наблюдения и границы — в [протоколе G1](протокол-g1-2026-11-02.md). Цель — выбрать доказанный способ получения и сохранения Pinterest-референсов до полной сборки UI. Общий замысел подтверждён; рабочесть механизмов не подтверждена.

## Порядок и gates

**G1 — до полной сборки:** доступный допустимый Pinterest-путь с реальными кандидатами, источниками и проверкой нативного визуального входа. Неподтверждённый Lens не заменяется молча описанием в слова.

**G2 — до подключения второго пользователя/самостоятельного пилота:** изоляция проектов, задач, авторизации и назначений при переключении аккаунтов.

**G3 — до передачи инструмента архитектору:** полезный landscape-fit, редактируемый импорт Figma и корректные независимые статусы двух экспортов.

## Матрица

| Проверка | Что делаем | Доказательство | Критерий |
|---|---|---|---|
| Доступ приложения/аккаунта | Уточнить официальный доступ, тип подключения, scopes и ограничения; проверить нужного пользователя | Протокол без токенов, username/проверенная личность, доступные операции | Нет обещания поддержки любого аккаунта без доказательства |
| Текстовый discovery | Короткие ландшафтные запросы Pinterest | Реальные pin ID/URL, доступные изображения, время, число уникальных | Действительно новые кандидаты, не только поиск собственных сохранений |
| Lens внешнего примера | Пример выбран пользователем, native image query в доступном интерфейсе/допустимой интеграции | Вход и его существенные признаки, путь запуска, результаты со ссылками | Запрос реально визуальный; оценена полезность для ландшафта |
| Pin/crop visual search | Целый пин и нужный фрагмент | Seed, область, результаты | Известно, чем управляет пользователь и что выбирается автоматически |
| Related | Расширить от удачного пина | Связь seed → candidates и отличия от Lens | Нет подмены одного механизма другим в отчёте |
| Eagle/OSS кандидаты | По необходимости проверить наиболее подходящий документированный/разрешённый путь | Версия/commit, лицензия, входы, реальный ответ | Чтение source отделено от runtime-успеха |
| Secret board и Save Pin | Явно создать тестовую secret board или выбрать подтверждённую; сохранить просмотренный набор | Владелец, SECRET, ID выбранных/сохранённых пинов, отдельные ошибки | Не новая публикация копий, не случайная публичная доска |
| Figma 25 изображений | Явно запустить плагин в тестовом Design-файле | Отдельные объекты/подписи/URL, количество, ошибки, расход памяти/время | Новый редактируемый фрейм; источники совпадают |
| Повтор и частичный сбой | Смоделировать таймаут после записи, сетевой сбой и повтор одного target | Квитанции до/после, реальные объекты | Нет дублей и повторного успешного target |
| Два аккаунта | Переключение при поиске, замене, незавершённом экспорте и повторном входе | Протокол видимости и фактического получателя | Ни одна задача A не использует B и не раскрывается B |
| Перезапуск | Остановить/запустить локальный сервис на активном шаге | Сохранённый этап и восстановленный результат | Нет полной потери выбора и слепого повторения записей |

## Данные эксперимента

Использовать материалы, предоставленные для проверки, и публичные примеры. Не создавать «реальные клиентские брифы» из предположений. «Бионические МАФы» и «китайский сад» — темы из интервью; пять действительных задач подбирает главный архитектор.

Логировать дату, платформу/версию, подключение без секретов, вход, стратегию, ID/URL, результат, время, затраты, ограничение и вывод. Кандидаты не становятся утверждённым набором автоматически. Рекомендации доски проверять только на уже выбранных пинах; не заполнять её неотобранными кандидатами ради поиска.

## Решение по итогам

Выбрать минимально достаточный adapter и стек только по результатам. Если механизм недоступен или не соответствует условиям доступа, сохранить факты и согласовать изменение с пользователем. Не объявлять успешным заглушечный поиск, пустую выдачу или ручной обход обязательной функции.

См. [матрицу источников](../../idea/05-research/search-matrix.md), [риски идеи](../../idea/07-risks/README.md), [инварианты](../03-данные/правила-нерушимые.md), [roadmap](../08-дорожная-карта/roadmap.md).

## Дополнительные сценарии из premortem

До G3 проверить совпадение immutable snapshot с обоими target по pin ID/URL и версии asset. Во время теста запустить замену и доставить поздний callback: экспорт должен остаться привязанным к исходному снимку.

Дополнительно: ручная правка/потеря метки Figma при retry → конфликт без перезаписи; unknown без метода сверки → остановка без слепого повторения; конкурентные платные вызовы и cancel → корректный резерв; очистка при pending/paused/unknown → сохранение нужных assets. См. [риски архитектуры](../07-нефункциональные/риски-архитектуры.md).

При сверке Pinterest учитывать source→saved mapping: сохранённый экземпляр может получить другой ID. См. [ADR 0002](журнал-решений/2026-11-02-pin-id-после-сохранения.md).

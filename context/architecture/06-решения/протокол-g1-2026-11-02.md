# Практические проверки G1 — 2026-11-02

Статус: **частично выполнено**. Есть экспериментальный код и реальные UI-наблюдения; полноценное приложение ещё не собрано. Это продолжение исходного [исследования](../../idea/05-research/README.md), которое выполнялось без аккаунтов.

## Среда и метод

Windows, Node.js 24, управляемый браузер Playwright. Пользователь вручную вошёл в свой Pinterest; видимый профиль проверен по UI. В контексте используется обозначение «тестовый аккаунт»; приватная квитанция хранится отдельно от документов.

Использованы стандартные UI-действия и чтение отрендеренных DOM-ссылок/изображений. Cookies, localStorage, скрытое состояние приложения, auth headers и внутренние HTTP endpoints не извлекались. Защиты и CAPTCHA не обходились.

## Инженерный вывод

Управляемый browser UI — подтверждённый технический кандидат: текст, внешний JPG Lens, crop и save действительно доступны в текущем аккаунте. Не требуется отказываться от нативного поиска в пользу только AI→текст.

Для постоянного adapter ещё нужны воспроизводимый самостоятельный запуск, авторизация/изоляция, обработка ограничений, проверка условий выбранного способа доступа и оценка на других заданиях. Однократный успех UI не доказывает публичный Lens API, Standard-доступ, поддержку всех аккаунтов или устойчивость к изменениям сайта.

G1 целиком остаётся открытым до фиксации достаточного способа интеграции и его ограничений. G2/G3 не пройдены. Это не основание считать продукт или самостоятельный пилот готовыми.

## Обнаруженное изменение модели

Сохранять в квитанции sourcePinId/sourcePinUrl и savedPinId/savedPinUrl отдельно, вместе с владельцем и доской. Совпадение проверять по происхождению операции и медиа/назначению, а не по равенству IDs. См. [ADR 0002](журнал-решений/2026-11-02-pin-id-после-сохранения.md).

Платные AI-вызовы не выполнялись.

## Диагностика manifest.api

Пользователь сообщил ошибку импорта: Expected manifest.api to have type string but got undefined. Правильный PMA manifest проверен как UTF-8 JSON с api=1.0.0; main/ui существуют. Первое чтение только путей localFileExtensions в настройках Figma показало регистрацию служебного manifest Codex вместо PMA; у него api отсутствует. Это ошибка выбора файла, а не доказанная несовместимость Plugin API.

При следующей проверке по просьбе пользователя через Computer Use правильный PMA manifest уже зарегистрирован вместе с ошибочными записями Codex manifest, code.js и ui.html. Регистрация пути не доказывает принятие манифеста валидатором Figma. Следующий скриншот пользователя показал «Manifest issue» именно у PMA; прежний вывод, что достаточно запустить плагин, был преждевременным. Запрошено открытие «Show error details…» у PMA, точная причина его собственного предупреждения пока не установлена. Локальный сервер отвечает 200 и отдаёт пакет из 25 изображений; node --check для code.js проходит.

Accessibility подтверждает открытый тестовый файл и сообщение об ошибке; восстановление Computer Use с новым сеансом и повторным выбором окна не устранило window capture timed out / coordinate input geometry is unavailable. Клавиатурные действия не дали наблюдаемого перехода. Конфигурация Figma не изменялась программно; живой запуск по-прежнему не засчитан.

После ручного открытия Show error details и Console Computer Use прочитал точную ошибку PMA: `Manifest error: Invalid value for devAllowedDomains. 'http://127.0.0.1:8787' must be a valid URL.` В plugin/manifest.json и запросе plugin/ui.html адрес заменён на `http://localhost:8787`. Сервер продолжает слушать только 127.0.0.1; расширение сетевого доступа не требуется. Это отдельная причина предупреждения PMA, помимо ошибочно импортированного служебного manifest Codex. Приём исправления Figma и живой запуск ещё требуют наблюдения.

После правки прямая проверка подтвердила совпадение origin в manifest/fetch, синтаксис code.js и UI script, HTTP 200 через localhost, CORS * для Origin: null и 25 изображений в техническом пакете. Пользователю предложено повторно открыть PMA в Development для проверки принятия манифеста.

## Подтверждённый локальный импорт и повтор

После сообщения пользователя «вроде работает» независимое чтение файла обнаружило новый фрейм [G1 · Локальный плагин · 25 технических референсов](https://www.figma.com/design/FILE_KEY?node-id=10-2), ID 10:2. Это другой фрейм, чем исходный коннекторный 2:16. Проверка подтвердила 107 потомков, 25 отдельных image rectangles с непустыми imageHash и 25 ссылок, каждая совпадает с Pinterest pin ID своей карточки. В окне самого плагина Computer Use прочитал результат повторного импорта с тем же ID: «Этот пакет уже есть в файле. Дубликат не создан».

При проверке найдено различие поведения resize текста: в native Plugin API подписи получили textAutoResize=NONE и наезжали на ссылки. В переносимом ядре и собранном code.js resize перенесён перед установкой HEIGHT. Уже созданные 52 текстовых объекта исправлены точечно через коннектор с загрузкой их текущих шрифтов. Итог 1776×2017, 25 подписей, Inter, пересечений подписи/ссылки нет; финальный screenshot проверен. Первичный native-import и последующая коннекторная коррекция текста явно различаются в квитанции.

Минимальная локальная связка Figma и повтор того же пакета подтверждены. Общий G1 остаётся частичным из-за незавершённого самостоятельного Pinterest-adapter; эти результаты не закрывают изоляцию аккаунтов, pairing, конфликты ручных правок или восстановление частичного импорта.

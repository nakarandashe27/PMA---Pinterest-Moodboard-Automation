# Нерушимые правила

Статус: целевые инварианты; должны проверяться реализацией.

1. Владелец проекта, брифа, запуска, выбора и экспорта совпадает; проверка на каждом действии.
2. Подключение для задания определяется его сохранённым владельцем, а не глобальным активным аккаунтом.
3. Нельзя экспортировать кандидат, которого нет в зафиксированном подтверждённом снимке.
4. Последующая замена/снятие выбора не меняет уже отправляемый снимок.
5. У каждого экспортируемого референса есть реальный Pinterest pin ID и каноническая ссылка. Подпись/причина не выдаётся за первоисточник.
6. Назначение Pinterest принадлежит ожидаемому аккаунту и подтверждено как SECRET. У API публичность по умолчанию не принимается как безопасный результат.
7. Сохраняются исходные пины; создание новых копий не является эквивалентным экспортом.
8. Два экспорта независимы. Успех одного не скрывает сбой другого.
9. Повтор одной попытки восстанавливает её результат; новый фрейм создаётся на новый экспорт/подборку, а не на сетевой retry.
10. Существующие ручные правки Figma не перезаписываются повторным поиском.
11. Недобор, недоступный пин, неопределённый тип картинки и частичный экспорт показываются честно.
12. Секреты не попадают в модель, документы, обычные логи и экспортируемый пакет.
13. После отмены не начинаются новые внешние записи. Неопределённый результат запроса сначала сверяется.
14. Неизвестные AI-поля, инструкции в метаданных и произвольные destination ID не управляют инструментами.
15. created_at не позже updated_at; удалённые/отключённые объекты не возвращаются обычным запросом.

См. [права](../02-ядро/права-доступа.md), [модель](сущности.md), [поток](../04-потоки/сценарий-и-состояния.md), [безопасность](../07-нефункциональные/безопасность.md).

## Дополнительные проверки целостности

Выбранный снимок фиксирует pin ID/URL и версию проверенного asset, а не только текущий набор ID карточек. Поздний callback и замена во время экспорта не меняют отправляемую версию. Если источник изменился или недоступен до записи, это отдельный конфликт/ошибка, а не успех старого выбора.

G3 сверяет snapshot с фактическим набором обоих назначений через явное отображение sourcePinId→savedPinId для Pinterest; IDs не обязаны совпадать; локальные квитанции без readback/проверки результата не являются достаточным доказательством. При unknown без проверенного способа сверки автоматический retry запрещён.

Метки Figma не дают права перезаписывать ручные изменения. Резервирование расходов выполняется до платного вызова; очистка защищает активные и неопределённые операции.

См. [наблюдение о saved ID](../06-решения/журнал-решений/2026-11-02-pin-id-после-сохранения.md).

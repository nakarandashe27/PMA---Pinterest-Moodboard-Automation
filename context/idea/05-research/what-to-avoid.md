# Чего избегать

- Считать UI-функцию Pinterest или пример OSS гарантией устойчивого программного доступа. [Lens help](https://help.pinterest.com/en/article/pinterest-lens) описывает пользовательскую функцию, а [официальный Search API](https://github.com/pinterest/pinterest-python-generated-api-client/blob/main/docs/SearchApi.md) — отдельные контракты (проверено 2026-11-02).
- Сужать визуальные примеры до текстовой подписи до проверки native Lens. Пользователь явно потребовал исследовать собственные алгоритмы Pinterest: [Q26](../04-mvp/decisions.md).
- Строить весь UI до доказательства получения источников и записи в секретную доску.
- Приравнивать свежий commit, README или название метода `visual_search` к работающему поиску по произвольному JPG. Входы разных [OSS-кандидатов](analogs.md) различаются.
- Имитировать человека ради обхода ограничений. Pinterest требует предварительного разрешения на неавторизованный автоматизированный сбор; вход в аккаунт сам по себе не меняет это. Источник: [Terms of Service](https://policy.pinterest.com/en/terms-of-service) (проверено 2026-11-02). Доступный и допустимый способ получения данных — часть первого технического этапа.
- Делать бесконечную выдачу, добивать число нерелевантными изображениями или заменять удачные карточки вместе с неудачными.
- Называть источник пина автором фотографии без подтверждения; выдумывать тип растения, климат, конструкцию или статус реализации.
- Считать JSON-каталог автоматически готовым семантическим поиском, а исходный URL картинки — вечным файловым архивом.
- Смешивать авторизацию разных аккаунтов или повторять оба экспорта после сбоя только одного.

См. [сценарий](../02-vision/day-in-the-life.md), [кандидаты](analogs.md), [принципы](../06-principles/README.md).

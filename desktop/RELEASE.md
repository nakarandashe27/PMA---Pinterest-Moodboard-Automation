# Выпуск PMA для Windows (8D.6)

## Сборка

```bash
npm run desktop:dist
```

Команда собирает UI и плагин Figma, затем установщик `release/PMA-Setup-<версия>-x64.exe` (electron-builder 26.18.0, NSIS, Electron 45.2.3). После этого `scripts/verify-package.mjs` проверяет состав по allowlist и пишет `<установщик>.sha256`. Если проверка не прошла, выпуска нет.

Что внутри (allowlist в `package.json` → `build.files`):

- `desktop/` (код без `smoke.mjs`), `server/*.mjs` (без `server/index.mjs` и тестов), два парсера из `spikes/pinterest-g1/`, собранный `dist/`;
- из зависимостей только `playwright`/`playwright-core`;
- в ресурсах только `app.asar`, `icon.ico` и `figma-plugin/` (manifest, code.js, ui.html; протокол 2).

`.local`, `output`, `context`, тестов, БД, профилей, cookies, ключей, пользовательских изображений и G1-пакета внутри нет; проверка падает, если что-то из этого попадёт. Electron fuses: запрещены `ELECTRON_RUN_AS_NODE` и `NODE_OPTIONS`, загрузка только из `app.asar` с проверкой целостности. Отладочные аргументы `--inspect` оставлены: без них не работает автоматическая проверка установленной программы.

## Установка

Обычная установка для текущего пользователя Windows: без прав администратора, путь можно выбрать, ярлыки создаются на рабочем столе и в «Пуске». Тихая установка: `PMA-Setup-<версия>-x64.exe /S` (в свою папку — `/S /D=<путь>`, последним аргументом). Данные лежат не в папке программы, а в `%LOCALAPPDATA%\PMA`.

## Передача и проверка подлинности

Установщик **не подписан**. Windows SmartScreen может предупредить о неизвестном издателе; отключать защиту не нужно, решение принимает владелец ПК. Передавайте файл вместе с SHA-256 из `.sha256` по согласованному каналу; получатель сверяет сумму:

```bash
certutil -hashfile PMA-Setup-0.1.1-x64.exe SHA256
```

Подпись и доверенный канал распространения — открытый выпускной gate (не решён).

## Ручное обновление

1. Закрыть PMA (крестик) и окно плагина PMA в Figma.
2. Запустить новый установщик поверх (тот же путь).
3. Открыть PMA. Если меняется схема данных, перед миграцией автоматически создаётся backup в `%LOCALAPPDATA%\PMA\backups`.
4. Запустить плагин в Figma заново. Папка плагина не меняется (`%LOCALAPPDATA%\PMA\integrations\figma-plugin`), повторный импорт не нужен.

Критическое обновление делается той же процедурой; фонового загрузчика нет.

## Удаление

«Установка и удаление программ» → PMA. Программа и ярлыки удаляются; проекты, учёт AI, ключи, профили Chrome и backup в `%LOCALAPPDATA%\PMA` остаются. Удаление локальных данных владельцем и сброс пароля без npm пока не реализованы.

## Проверено 2026-11-10 (ПК разработчика, Windows 10 19045 x64, без прав администратора)

- `PMA-Setup-0.1.0-x64.exe` 119.5 МБ; состав прошёл allowlist (97 файлов приложения, 203 файла зависимостей).
- Установка в `%LOCALAPPDATA%\Programs\PMA Тест 8D6` (пробел + кириллица); все 23 проверки `PMA_SMOKE_EXE=<PMA.exe> node desktop/smoke.mjs` прошли на установленной программе с PATH без Node/npm/Codex: IPC, медиа, DPAPI-ключ, мост Figma, блокировка, выход и аварии с настоящим Chrome PMA. Файлы установки после запусков не изменились.
- Обновление 0.1.0 → 0.1.1 поверх: в диагностике новая версия; проект, подборка, квитанция Pinterest, учтённый AI-вызов и папка плагина сохранены.
- Удаление: программа и ярлык удалены, данные/ledger/папка плагина остались; повторная установка читает их.

Не проверено: чистый ПК и ПК архитектора (D0/D1), живой Figma на другом ПК (D20), установка для всех пользователей, SmartScreen на чужом ПК.
